# Unit 5: An Introduction to Testing – Code Complexity Reflection

## Overview

This activity forms part of Unit 5 of my ePortfolio, focusing on the concept of code complexity and how it relates to software testing, maintainability, and quality. It also considers the role that AI tools, such as ChatGPT, can play in supporting developers to reduce complexity and improve code quality.

## What is Code Complexity?

Code complexity describes how easy (or difficult) a piece of code is to understand, maintain, and modify. Several factors contribute to complexity, including the volume of code written, the number and depth of dependencies, the depth of nesting and inheritance, and the algorithms used. The skill and experience of the developer also plays a significant role in how complex a solution ends up being.

High complexity slows down maintenance, makes bugs harder to locate and fix, and increases the risk associated with making changes. For this reason, low complexity is generally a key goal of good software development practice.

Complexity can be measured in several ways:

- **Lines of source code** – a simple count of how much code exists.
- **Maintainability index** – a score from 0–100 derived from cyclomatic complexity, comment density, and lines of code; higher scores indicate more maintainable code.
- **Cyclomatic complexity** – the number of independent paths through the code, which also indicates how many test cases are needed for full path coverage.
- **Rework ratio** – the proportion of total development time spent fixing defects or reworking code.
- **Halstead volume** – a measure based on the number of distinct operators/operands and how often each is used, representing the overall "volume" of information in a program.

## Reflection on Guo et al. (2024)

> Guo, Q. et al. (2024) 'Exploring the Potential of ChatGPT in Automated Code Refinement: An Empirical Study', *46th International Conference on Software Engineering (ICSE '24)*, New York (USA), 14–20 April. Association for Computing Machinery, pp. 1–13.

### What do I agree with in this article?

This study investigates how well ChatGPT can refine existing code based on human-written code review comments, comparing its performance against CodeReviewer, a specialised state-of-the-art tool for this task. The authors found that ChatGPT produced refinements closer to the "correct" human-written fix than the existing benchmark tool, while also identifying specific reasons why ChatGPT sometimes underperforms, and suggesting strategies to address these.

I agree with the underlying premise that AI tools have real potential to support the code review and refinement stage of development. From my own experience writing Python scripts for cybersecurity labs and CTF challenges, I have found that asking an AI tool to review a function against a specific piece of feedback (for example, "this function has too many nested conditionals" or "this variable naming is unclear") often produces a quick, usable suggestion that I can then evaluate and adapt. This mirrors the study's framing of AI as a tool for *refinement* rather than wholesale code generation — it works on an existing piece of code in response to a specific instruction, which is a much narrower and more achievable task than generating an entire solution from scratch.

I also agree with the study's more cautious conclusion: that ChatGPT's performance, while promising, is not perfect and has identifiable weaknesses. This matches my own experience that AI-suggested refinements sometimes address the surface-level issue raised in a comment without fully considering the wider context of the codebase, occasionally introducing new issues elsewhere. This reinforces my view that AI-assisted refinement works best as part of a human-in-the-loop process: the developer still needs to understand the code well enough to judge whether a suggested change is appropriate, rather than accepting it automatically. This is directly relevant to reducing complexity, since a refinement that "fixes" one metric (for example, shortening a function) but introduces a subtle bug or an unclear dependency elsewhere has not genuinely reduced overall complexity — it has just moved it.

## Reflection on Liu et al. (2024)

> Liu, Z. et al. (2024) 'No Need to Lift a Finger Anymore? Assessing the Quality of Code Generation by ChatGPT', *IEEE Transactions on Software Engineering*, 50(6), pp. 1548–1584.

### My understanding of the complexity of artificially generated code

This study carried out a large-scale assessment of code generated by ChatGPT across hundreds of algorithm problems and multiple programming languages, evaluating the output specifically on correctness, complexity, and security. One of the key findings relevant to this unit is that, when ChatGPT is asked to fix or improve a piece of code over multiple rounds of interaction, the *complexity* of the resulting code tends to stay the same or increase, even where correctness or security improves. The study also notes that ChatGPT's outputs are not fully deterministic, meaning that asking the same question more than once can produce code with different levels of complexity, correctness, and security.

My understanding from this is that AI-generated code should not be assumed to be inherently "clean" or low-complexity simply because it comes from a modern, capable model. An AI tool can be very effective at solving the *functional* problem — making the code work, or fixing a specific bug or vulnerability — without necessarily producing the *simplest* or most maintainable solution. In some cases, the process of iteratively patching code (for example, adding extra conditionals or validation checks to address an issue) can make a function more complex over time, even as it becomes more correct or secure. This is an important distinction for testing: a piece of code can pass all functional tests and still have high cyclomatic complexity, poor maintainability, or a large Halstead volume, all of which make it harder to test thoroughly and maintain in future.

The non-determinism finding also stood out to me. If complexity can vary between runs for the same prompt, then complexity metrics cannot simply be "trusted" once and forgotten — they need to be checked again whenever AI-assisted changes are made, in the same way that tests need to be re-run after any code change. This reinforces the idea that AI tools are best used as an aid within a development and testing process that still includes human review and standard complexity/quality checks (for example, running a maintainability index or cyclomatic complexity tool before and after an AI-assisted change), rather than as a replacement for that process.

## Key Takeaways

- AI tools such as ChatGPT can meaningfully support code refinement and bug/vulnerability fixing, but their output should be reviewed rather than accepted automatically.
- Functional correctness and low complexity are not the same thing — AI-assisted fixes can resolve a bug while leaving complexity unchanged or increased.
- Complexity metrics (lines of code, maintainability index, cyclomatic complexity, rework ratio, Halstead volume) remain useful tools for checking the *quality* of both human-written and AI-assisted code, not just its correctness.
- Because AI output can vary between runs, complexity should be re-checked after AI-assisted changes, in the same spirit as re-running tests after any code modification.
