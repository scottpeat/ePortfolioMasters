## 🏆 Chosen Portfolio Framework: Driscoll's "What?" Model

For all subsequent reflections and milestone tracking within this ePortfolio, **John Driscoll’s (1994 / 2007) Framework** has been selected as the optimum model. 

While frameworks like Gibbs' (1988) are excellent for tracking personal or emotional growth, Driscoll's pragmatic approach mirrors the exact lifecycle of technical software engineering and incident response:

### 1. WHAT? (The Triggering Event)
* **Engineering Alignment:** Incident Detection / Vulnerability Identification.
* **Application:** What code flaw, design weakness, or architectural constraint was encountered? (e.g., executing the unanchored regex loop or identifying memory unsafety in C).

### 2. SO WHAT? (The Critical Analysis)
* **Engineering Alignment:** Risk Assessment / Impact Analysis.
* **Application:** What are the security, performance, or systems-level implications of this finding? What does academic literature (e.g., Cifuentes & Bierman, 2019) or industry data tell us about the threat vector?

### 3. NOW WHAT? (The Action Plan)
* **Engineering Alignment:** Patch Deployment / Continuous Mitigation.
* **Application:** What tactical adjustments, secure coding standards, or defensive tools (like Pylint and SAST scanners) must be integrated into the workflow to eliminate this risk permanently?
